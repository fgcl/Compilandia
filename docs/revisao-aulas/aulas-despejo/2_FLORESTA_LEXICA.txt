=== AULA ANIMADA [BASICO] Cortar a linha  (id=TOKENS, ~156s, 21 passos, exemplo começa no passo 3)
1. [BYTE] O parser trabalha com palavras, como nomes e operadores. Mas o arquivo chega caractere por caractere.
     palco: Letras demais | i | f | ( | x | 1 | > | = | 1 | 0 | )
2. [BYTE] Quantas palavras o parser quer ver nesta linha? Toque no número.
     palco: Letras demais | i | f | ( | x | 1 | > | = | 1 | 0 | ) | 5 | 6 | 13
     PERGUNTA(toque): certas=[6] erradas=[5, 13]
       dica: Nome, número, sinal e parêntese contam. Espaço não conta.
       acerto: Isso. Seis palavras no lugar de treze caracteres.
3. [BYTE] Por isso existe a análise léxica. O analisador léxico, ou scanner, junta os caracteres em tokens antes do parser.
     palco: Letras demais | i | f | ( | x | 1 | > | = | 1 | 0 | ) | if | ( | x1 | >= | 10 | )
4. [BYTE] Para o computador, esta linha é só uma fila de caracteres.
     palco: Scanner | c | o | n | t | a | = | 1 | 0 | + | x | 1 | ;
5. [BYTE] O scanner anda por ela da esquerda para a direita e separa os pedaços. Cada pedaço vira um token.
     palco: Scanner | c | o | n | t | a | = | 1 | 0 | + | x | 1 | ; | conta | = | 10 | + | x1 | ; | entram letras | saem tokens
6. [BYTE] Cada token tem uma classe: identificador, número ou operador. É a classe que o parser enxerga.
     palco: Scanner | c | o | n | t | a | = | 1 | 0 | + | x | 1 | ; | conta | = | 10 | + | x1 | ; | ID | NUM | OP
7. [BYTE] Espaços, quebras de linha e comentários são descartados aqui. Nenhuma fase depois os vê.
     palco: Scanner | conta | = | 10 | + | x1 | ; | ID | NUM | OP | c | o | n | t | a | = | 1 | 0 | + | x | 1 | ;
8. [BYTE] Sua vez. Toque nos dois cortes desta linha.
     palco: Onde corta? | x | > | = | 1 | 0
     PERGUNTA(toque): certas=[, ] erradas=[, ]
       dica: O maior ou igual fica inteiro, e o número também.
       acerto: Isso. Três tokens: x, maior ou igual, e dez.
9. [BYTE] Essa é a regra do maior casamento: o scanner sempre pega o pedaço mais longo possível. Por isso conta2 é um nome só.
     palco: Maior casamento | > | = | >= | conta2
10. [BYTE] O texto exato do pedaço é o lexema. A classe dele é o token. Vários lexemas diferentes têm o mesmo token.
     palco: Lexema e token | x1 | ID | lexema | token
11. [BYTE] A receita do scanner tem três passos. Ela fica aqui na tela.
     palco: Receita | 1. Pule espaços e comentários. | 2. Pegue o pedaço mais longo que forma token. | 3. Dê a classe: palavra-chave, ID, NUM, OP...
12. [BYTE] Por que conta2 virou um token só, e não dois? Toque no passo.
     palco: Receita | 1. Pule espaços e comentários. | 2. Pegue o pedaço mais longo que forma token. | 3. Dê a classe: palavra-chave, ID, NUM, OP... | conta2
     PERGUNTA(toque): certas=[2. Pegue o pedaço mais longo que forma token.] erradas=[1. Pule espaços e comentários., 3. Dê a classe: palavra-chave, ID, NUM, OP...]
       dica: O scanner segue lendo enquanto o pedaço ainda forma um nome.
       acerto: Isso. Passo dois, o maior casamento.
13. [BYTE] Passo três: if é palavra reservada e tem classe própria. Já ifx é um identificador comum, pelo maior casamento.
     palco: Receita | 1. Pule espaços e comentários. | 2. Pegue o pedaço mais longo que forma token. | *3. Dê a classe: palavra-chave, ID, NUM, OP... | if | ifx
14. [BYTE] Entram letras, saem tokens. Agora quem corta é você.
     palco: Outra linha | w | h | i | l | e | ( | i | < | = | n | ) | i | + | + | ;
15. [BYTE] A linha começa com while. Qual é a classe dele? Toque.
     palco: Outra linha | w | h | i | l | e | ( | i | < | = | n | ) | i | + | + | ; | ID | palavra-chave
     PERGUNTA(toque): certas=[palavra-chave] erradas=[ID]
       dica: While está na lista de palavras reservadas da linguagem.
       acerto: Isso. Palavra-chave, como if e for.
16. [BYTE] Agora o fim da linha. Toque nos dois cortes deste pedaço.
     palco: Outra linha | w | h | i | l | e | ( | i | < | = | n | ) | i | + | + | ; | i | + | + | ;
     PERGUNTA(toque): certas=[, ] erradas=[]
       dica: O mais mais fica inteiro, como o maior ou igual.
       acerto: Isso. Três tokens: o nome, o mais mais e o ponto e vírgula.
17. [BYTE] Quantos tokens saem da linha inteira? Toque no número.
     palco: Outra linha | w | h | i | l | e | ( | i | < | = | n | ) | i | + | + | ; | 7 | 9 | 17
     PERGUNTA(toque): certas=[9] erradas=[7, 17]
       dica: Conte cada nome, cada sinal e cada parêntese. Pule os espaços.
       acerto: Isso. Essa linha gera nove tokens.
18. [BYTE] Nove tokens, cada um com sua classe. É isso que o parser recebe.
     palco: Outra linha | w | h | i | l | e | ( | i | < | = | n | ) | i | + | + | ; | while | ( | i | <= | n | ) | i | ++ | ;
19. [BYTE] Como o scanner corta este trecho? Um colega cortou assim. Certo ou errado?
     palco: Erros comuns | Em x>=10, o scanner gera os tokens x, >, = e 10. | certo | errado

       dica: O scanner pega sempre o pedaço mais longo que forma um token.
       acerto: Isso. Pelo maior casamento, maior ou igual é um token só. São três tokens, não quatro.
20. [BYTE] Outro erro: confundir token com lexema. Lexema é o texto que estava no arquivo. Token é a classe que o parser recebe.
     palco: Erros comuns | Certo: x>=10 dá três tokens: x, >= e 10. É o maior casamento. | *Errado: Token e lexema são a mesma coisa. | *Certo: Lexema é o texto (conta2). Token é a classe (ID).
21. [BYTE] Resumindo: a análise léxica transforma caracteres em tokens. Ela usa o maior casamento, separa lexema de classe e joga fora espaços e comentários.
     palco: Resumo | O scanner lê caracteres e entrega tokens ao parser. | Maior casamento: sempre o pedaço mais longo que forma token. | Lexema é o texto; token é a classe. Espaço e comentário somem.

=== AULA ANIMADA [PEGADINHA] Por que ifa não é if  (id=TOKENS/porqueifanãoéif, ~39s, 6 passos, exemplo começa no passo null)
1. [BYTE] Olhe esta linha: ifa igual a um. O scanner começa pelo i.
     palco: ifa = 1; | *i | f | a | = | 1 | ;
2. [BYTE] Depois do i vem o f. O pedaço agora é if, que é palavra reservada.
     palco: ifa = 1; | *i | *f | a | = | 1 | ;
3. [BYTE] Ele fecha o token agora? Toque na última letra desse token.
     palco: ifa = 1; | i | f | a | = | 1 | ;
     PERGUNTA(toque): certas=[a] erradas=[f, =]
       dica: O scanner estica enquanto der. O a ainda cabe num nome.
       acerto: Isso. O a ainda cabe, então o token é ifa.
4. [BYTE] Maior casamento: fica o pedaço mais comprido. Por isso ifa é um nome comum.
     palco: ifa = 1; | *i | *f | *a | = | 1 | ; | ifa | = | 1 | ;
5. [PROF] A palavra reservada só ganha no empate. If sozinho tem o mesmo tamanho nas duas regras.
     palco: ifa = 1; | i | f | a | = | 1 | ; | ifa | = | 1 | ;
6. [BYTE] Ordem de decisão: primeiro o tamanho, depois a reservada.
     palco: MAIOR CASAMENTO

=== AULA DE LEITURA [STORY] O caixa do supermercado
[NARRADOR] Supermercado em dia de promoção. A Lexi está no caixa, passando os produtos da esteira um por um.
[LEXI] Bip! 'Guaraná 2L'. Bip! 'Pão francês'. Bip! 'Guaraná lata'. Pra mim, cada produto vai para uma CATEGORIA no cupom fiscal.
[PROF] Repare em três coisas diferentes: o produto concreto na mão dela, a categoria impressa no cupom e a regra que diz qual produto vai em qual categoria.
PASSOS Supermercado → compilador:
    1. O produto concreto ('Guaraná 2L') → **lexema**: o pedaço de texto real do programa, como `contador` ou `42`.
    2. A categoria no cupom (BEBIDA) → **token**: o nome da classe, como `id` ou `num`.
    3. A regra ('todo líquido engarrafado é BEBIDA') → **padrão**: a descrição de quais lexemas pertencem ao token, como 'letra seguida de letras ou dígitos'.
[BYTE] Então 'Guaraná 2L' e 'Guaraná lata' são lexemas diferentes do MESMO token?
[PROF] Exatamente! Como `x` e `total`: lexemas diferentes, mesmo token `id`.
TEXTO: Mas no cupom a categoria sozinha não basta: precisa saber QUAL bebida foi. Por isso o token carrega um **atributo**: ⟨id, ponteiro para `total` na tabela de símbolos⟩.
PREVEJA: Em `if (x >= 10)`, qual é o LEXEMA do token de comparação?
    (     ) relop (operador relacional)
    (certa) >=
    (     ) x >= 10
    (     ) if
    EXPLICACAO: `>=` é o texto real (lexema). 'relop' é o nome do token, a categoria.
[LEXI] E tem mais: eu sempre pego o MAIOR pedaço possível. Vendo `>=`, não corto em `>` e `=`. É como ler 'guarda-chuva' como uma palavra só, e não 'guarda' + 'chuva'.
DESTAQUE NO_DUMB_QUESTIONS: P: E o `if`? Ele também casa com 'letras seguidas de letras', o padrão de identificador! R: Empate. Palavras-chave são **reservadas**: a regra delas tem prioridade. Já `iff` é mais comprido que `if`, então pelo maior casamento vira identificador.
WIDGET TOKENIZE gramatica= entrada=if (iff >= 10) whilex = whilex + 1; legenda=Repare: `iff` e `whilex` são identificadores, não palavras-chave!
DESTAQUE REAL_WORLD: Por isso em C você não pode chamar uma variável de `while`, mas pode chamar de `whilex`.
REVELAR: Na analogia, quem é lexema, quem é token e quem é padrão?
    RESPOSTA: Lexema = o produto concreto (o texto). Token = a categoria no cupom (a classe). Padrão = a regra que decide a categoria.

=== AULA DE LEITURA [WORKED] Montando a tabela de tokens
[PROF] Vamos montar a tabela lexema / token / atributo de uma linha, com calma.
CODIGO (Entrada):
    if (x >= 10) total += x;
PASSOS Resolvido:
    1. `if` → palavra-chave **if**. Também casa com id, mas palavra reservada vence. Sem atributo.
    2. `(` → delimitador **(**.
    3. `x` → **id**, atributo: ponteiro para x na tabela de símbolos.
    4. `>=` → **relop**, atributo GE. Maior casamento: não é `>` + `=`.
    5. `10` → **num**, atributo: o valor 10.
    6. `)` → delimitador **)**.
    7. `total` → **id**, ponteiro para total.
    8. `+=` → operador de atribuição composta **+=**.
    9. `x` → **id**, o MESMO ponteiro do primeiro x.
    10. `;` → delimitador **;**. Total: 10 tokens.
WIDGET TOKENIZE gramatica= entrada=if (x >= 10) total += x; legenda=Confira com a Lexi.
DESTAQUE WATCH_OUT: Os dois `x` geram dois TOKENS, mas a tabela de símbolos tem UMA só entrada para x. Token se repete; entrada na tabela, não.
TEXTO: Sua vez (exemplo esmaecido): `while (i <= n1) i++;`
REVELAR: Quantos tokens?
    RESPOSTA: 9: while, (, i, <=, n1, ), i, ++, ;
REVELAR: Qual é o token de `while`? E de `n1`?
    RESPOSTA: `while` é palavra-chave (reservada). `n1` é id: começa com letra e depois vem um dígito.
REVELAR: `<=` e `++` são um token cada ou dois?
    RESPOSTA: Um cada: maior casamento. `<=` é relop (LE); `++` é o operador de incremento.
WIDGET TOKENIZE gramatica= entrada=while (i <= n1) i++; legenda=Confira suas respostas.
DESTAQUE EXAM_TIP: Questão comum: 'quantos tokens há no trecho?'. Armadilhas: operadores de dois caracteres (`<=`, `==`, `++`), número com ponto (`3.14` é UM token), string (`"a b c"` é UM token) e comentários (zero tokens).

=== AULA DE LEITURA [SOCRATIC] Por que existe um analisador léxico?
[PROF] Vou te fazer perguntas. Chute sem medo: errar aqui é parte do método.
PREVEJA: O analisador léxico descarta espaços e comentários. Por quê?
    (certa) Porque eles não mudam o significado do programa (na maioria das linguagens)
    (     ) Porque ocupam memória demais
    (     ) Porque o sintático tem preguiça
    (     ) Porque é proibido usar espaços em C
    EXPLICACAO: Espaço só separa lexemas; depois disso não serve pra mais nada. (Python é a exceção famosa: a indentação vira tokens INDENT/DEDENT!)
PREVEJA: Em `count2=count2+1`, o que é `count2`?
    (     ) Dois tokens: id `count` e num `2`
    (certa) Um único token id
    (     ) Erro léxico
    (     ) Uma palavra-chave
    EXPLICACAO: O padrão de id é letra seguida de letras OU dígitos, e o maior casamento engole o 2 junto.
PREVEJA: `>=` deve virar quantos tokens?
    (certa) 1
    (     ) 2
    EXPLICACAO: Um só. Regra do **maior casamento** (maximal munch): pegue o maior prefixo da entrada que casa com algum padrão.
[BYTE] Mas e o `if`? Ele casa com o padrão de identificador E com o de palavra-chave. Empate!
REVELAR: Como desempatar `if`? E por que `iff` não é palavra-chave?
    RESPOSTA: Empate de MESMO tamanho: vence a regra listada primeiro, palavras-chave vêm antes de id. `iff` tem 3 letras: o maior casamento prefere o id de 3 letras ao `if` de 2.
PREVEJA: Em `fi (a == f(x))`, o léxico percebe que `fi` deveria ser `if`?
    (     ) Sim, é erro léxico
    (certa) Não: `fi` é um identificador válido
    EXPLICACAO: O léxico não enxerga o contexto: `fi` casa com o padrão de id. Exemplo literal do Livro do Dragão!
[PROF] Última: por que não deixar o sintático fazer tudo, lendo caractere por caractere?
REVELAR: Três motivos para separar análise léxica de sintática.
    RESPOSTA: 1) **Simplicidade**: a gramática não precisa falar de espaços e comentários. 2) **Eficiência**: técnicas especializadas (buffers, autômatos) leem caracteres muito rápido. 3) **Portabilidade**: as peculiaridades da entrada ficam isoladas no léxico.
DESTAQUE FIRESIDE: Léxico: 'Eu trabalho com caracteres; você, com tokens.' Sintático: 'E eu te chamo quando preciso: getNextToken()!', na prática o léxico é uma sub-rotina do sintático.
WIDGET TOKENIZE gramatica= entrada=fi (a == f(x)) x = 1; legenda=Veja: `fi` passa como identificador sem reclamação.

=== AULA DE LEITURA [FORMAL] Token, padrão e lexema: definições
TEXTO: **Token**: par ⟨nome-do-token, valor-de-atributo⟩. O nome é um símbolo abstrato que representa um tipo de unidade léxica (palavra-chave, identificador…); é o que o analisador sintático processa.
TEXTO: **Padrão**: descrição da forma que os lexemas de um token podem assumir. Para uma palavra-chave, é a própria sequência de caracteres; para identificadores, é uma estrutura casada por muitas cadeias.
TEXTO: **Lexema**: sequência de caracteres do programa fonte que casa com o padrão de um token e é identificada pelo analisador léxico como uma instância desse token.
CODIGO (Exemplos de tokens (Livro do Dragão, Fig. 3.2)):
    TOKEN       PADRÃO (informal)                    LEXEMAS
    if          caracteres i, f                      if
    else        caracteres e, l, s, e                else
    comparison  < ou > ou <= ou >= ou == ou !=       <=, !=
    id          letra seguida de letras e dígitos    pi, score, D2
    number      qualquer constante numérica          3.14159, 0, 6.02e23
    literal     qualquer coisa entre aspas           "core dumped"
TEXTO: Exemplo: `E = M * C ** 2` gera ⟨id, ptr E⟩ ⟨assign_op⟩ ⟨id, ptr M⟩ ⟨mult_op⟩ ⟨id, ptr C⟩ ⟨exp_op⟩ ⟨number, 2⟩.
CODIGO (Esqueleto de um analisador léxico):
    função getNextToken():
        pular espaços e comentários (contando linhas)
        lexemeBegin ← forward
        para cada padrão P, em ordem de prioridade:
            achar o MAIOR prefixo da entrada que casa com P
        escolher o maior prefixo; empate → padrão listado primeiro
        se nenhum casou: erro léxico (ex.: modo pânico)
        se for id: instalar/consultar na tabela de símbolos
        retornar ⟨nome, atributo⟩
DESTAQUE NO_DUMB_QUESTIONS: P: E quando nenhum padrão casa? R: Recuperação em **modo pânico**: apagar caracteres até achar um token válido. Outras ações possíveis: inserir, remover, substituir um caractere ou trocar dois adjacentes.
PREVEJA: Em `x = 3.14;`, quantos lexemas existem?
    (certa) 4
    (     ) 5
    (     ) 6
    EXPLICACAO: x, =, 3.14 e ;: o número com ponto é UM lexema só.

=== AULA DE LEITURA [STORY] O trem que lê palavras
[NARRADOR] Na Floresta Léxica passa um trenzinho. Ele só anda pelos trilhos pintados com a letra que está lendo.
[PROF] Cada estação é um **estado**. Cada trilho tem uma letra: é uma **transição**. Algumas estações têm bandeira de chegada: são os **estados finais** (de aceitação).
[BYTE] E como o trem decide se a palavra é aceita?
[PROF] Ele parte da estação inicial e lê a palavra letra por letra, seguindo os trilhos. Acabou a palavra numa estação com bandeira? Aceita! Ficou sem trilho, ou parou longe da bandeira? Rejeita.
WIDGET DFA gramatica= entrada=(a|b)*abb legenda=O trem do Livro do Dragão: aceita palavras de a's e b's que terminam em abb. Teste 'aabb' e 'abab'.
TEXTO: Esse trem é um **AFD** (autômato finito determinístico): em cada estação, para cada letra, há NO MÁXIMO um trilho. O maquinista nunca fica em dúvida.
[BYTE] E se tivesse dois trilhos com a mesma letra?
[PROF] Aí é um **AFN** (não determinístico): um trem mágico que se divide e segue TODOS os caminhos ao mesmo tempo, como num multiverso. E ainda tem trilhos ε, que ele pega sem ler letra nenhuma.
DESTAQUE FIRESIDE: AFN: 'Eu sou fácil de construir a partir da expressão regular!' AFD: 'Mas eu sou rápido: um passo por letra, sem dúvida nenhuma.' Os dois reconhecem exatamente as mesmas linguagens: as regulares.
PASSOS A fábrica de trens:
    1. **Expressão regular**: o desenho do trajeto, como `(a|b)*abb`.
    2. **Construção de Thompson**: transforma a ER num AFN, peça por peça (união, concatenação, fecho).
    3. **Construção de subconjuntos**: cada estação do AFD é um CESTO de estações do AFN onde o trem mágico poderia estar.
    4. **Minimização**: junta estações que se comportam igual. O AFD de `(a|b)*abb` fica com 4 estados.
PREVEJA: Um AFN com 3 estados vira um AFD com, NO MÁXIMO, quantos estados?
    (     ) 3
    (     ) 6
    (certa) 8
    (     ) 9
    EXPLICACAO: Cada estado do AFD é um SUBCONJUNTO dos estados do AFN: 2³ = 8 subconjuntos possíveis. Na prática, quase sempre são bem menos.
DESTAQUE REAL_WORLD: Lex/Flex fazem exatamente isso: você escreve as ERs dos tokens e eles geram o AFD que vira o coração do analisador léxico.
REVELAR: Na analogia, o que é estação, trilho, bandeira e trem mágico?
    RESPOSTA: Estado, transição, estado final (de aceitação) e AFN (que pode estar em vários estados ao mesmo tempo).

=== AULA DE LEITURA [WORKED] Construção de subconjuntos na mão
[PROF] Vamos converter um AFN em AFD com calma. Este AFN aceita as cadeias de a's e b's que terminam em ab.
CODIGO (AFN: em 0, lendo a, o trem pode ficar em 0 OU ir para 1 (não determinismo!)):
    estados: 0 (inicial), 1, 2 (final)
    0 --a--> 0     0 --b--> 0
    0 --a--> 1
    1 --b--> 2
TEXTO: Regra do jogo: cada estado do AFD é um **conjunto** de estados do AFN, e Dtran[T, x] = ε-fecho(move(T, x)). Este AFN não tem transições ε, então o ε-fecho não acrescenta nada.
PASSOS Resolvido:
    1. Início: A = ε-fecho({0}) = {0}.
    2. A com a: move({0}, a) = {0, 1} → novo estado **B**.
    3. A com b: move({0}, b) = {0} → é o próprio **A**.
    4. B com a: move({0, 1}, a) = {0, 1} → **B**.
    5. B com b: move({0, 1}, b) = {0, 2} → novo estado **C**.
    6. C com a: {0, 1} = **B**. C com b: {0} = **A**.
    7. Finais: os conjuntos que contêm o estado 2 → só **C**. Pronto: AFD com 3 estados.
CODIGO (Tabela de transição do AFD (→ inicial, * final)):
          a    b
    →A    B    A
     B    B    C
    *C    B    A
WIDGET DFA gramatica= entrada=(a|b)*ab legenda=O motor chega ao mesmo AFD de 3 estados. Compare!
TEXTO: Agora esmaecido: AFN para cadeias que terminam em **bb**: 0 --a,b--> 0, 0 --b--> 1, 1 --b--> 2 (final).
REVELAR: A = {0}. Calcule Dtran[A, a] e Dtran[A, b].
    RESPOSTA: Dtran[A, a] = {0} = A. Dtran[A, b] = {0, 1} = novo estado B.
REVELAR: Agora B = {0, 1}: com a? com b?
    RESPOSTA: B com a: {0} = A. B com b: {0, 1, 2} = novo estado C.
REVELAR: C = {0, 1, 2}: com a? com b? Quem é final?
    RESPOSTA: C com a: {0} = A. C com b: {0, 1, 2} = C. Final: C (contém o 2). AFD com 3 estados.

=== AULA DE LEITURA [FORMAL] ER, AFN e AFD: definições e algoritmos
TEXTO: **Expressão regular** sobre o alfabeto Σ: ε e cada a ∈ Σ são ERs; se r e s são ERs, então r|s, rs, r* e (r) também são. L(r|s) = L(r) ∪ L(s); L(rs) = L(r)L(s); L(r*) = (L(r))*.
TEXTO: Precedência: `*` (maior) > concatenação > `|` (menor), todas associativas à esquerda. Assim, `a|b*c` = `a|((b*)c)`.
TEXTO: **AFN**: (S, Σ, move, s₀, F), conjunto finito de estados S, alfabeto Σ, função de transição que leva (estado, símbolo ou ε) a um CONJUNTO de estados, estado inicial s₀ e estados finais F. **AFD**: caso especial sem transições ε e com exatamente um destino para cada par (estado, símbolo).
CODIGO (Algoritmo 3.23 (Livro do Dragão)):
    Construção de Thompson (ER → AFN):
      ε     :  i --ε--> f
      a     :  i --a--> f
      s|t   :  novo i --ε--> N(s) e N(t); finais de ambos --ε--> novo f
      st    :  final de N(s) se funde com o inicial de N(t)
      s*    :  i --ε--> N(s), i --ε--> f;
               final de N(s) --ε--> início de N(s) e --ε--> f
    Propriedade: N(r) tem no máximo 2 × (nº de símbolos e operadores de r) estados.
CODIGO (Algoritmo 3.20 (Livro do Dragão)):
    Construção de subconjuntos (AFN → AFD):
      Dstates ← { ε-fecho(s₀) }, não marcado
      enquanto existe T não marcado em Dstates:
          marque T
          para cada símbolo a:
              U ← ε-fecho(move(T, a))
              se U ∉ Dstates: adicione U (não marcado)
              Dtran[T, a] ← U
      finais: todo T que contém um estado final do AFN
TEXTO: **ε-fecho(T)**: estados alcançáveis a partir de algum estado de T usando só transições ε (inclui o próprio T). **move(T, a)**: estados alcançáveis a partir de T com UMA transição rotulada a.
PREVEJA: Qual é a precedência correta dos operadores?
    (     ) | > concatenação > *
    (certa) * > concatenação > |
    (     ) concatenação > * > |
    EXPLICACAO: Como na aritmética: * é a 'potência', concatenação a 'multiplicação' e | a 'soma'.
PREVEJA: Pela precedência, `ab*` significa…
    (     ) (ab)*
    (certa) a(b*)
    EXPLICACAO: O * se aplica só ao símbolo imediatamente à esquerda: um a seguido de zero ou mais b's.
WIDGET DFA gramatica= entrada=ab* legenda=Confirme: 'abab' é rejeitada.
DESTAQUE EXAM_TIP: Cai muito: (1) desenhar o AFN de Thompson de `(a|b)*abb` (11 estados, de 0 a 10); (2) aplicar subconjuntos e chegar a A, B, C, D, E, com E final; (3) minimizar juntando A e C → 4 estados. Saiba que ε-fecho({0}) = {0, 1, 2, 4, 7}.
DESTAQUE WATCH_OUT: Um AFN de n estados pode virar um AFD de até 2ⁿ estados (explosão exponencial), mas isso é raro na prática. Em troca, simular o AFD gasta só um passo por caractere.
REVELAR: Defina ε-fecho e move em uma linha cada.
    RESPOSTA: ε-fecho(T): estados alcançáveis a partir de T só por transições ε (incluindo T). move(T, a): estados alcançáveis a partir de T por exatamente uma transição rotulada a.

=== AULA DE LEITURA [MNEMONIC] Thompson Transforma, Subconjuntos Simplificam
DESTAQUE MNEMONIC: **T**hompson **T**ransforma (ER → AFN). **S**ubconjuntos **S**implificam o caos (AFN → AFD). E a **M**inimização **M**ata os estados repetidos.
DESTAQUE MNEMONIC: **N** de AFN = **N**ão sei para onde vou (vários caminhos). **D** de AFD = **D**ecidido (um caminho só).
DESTAQUE MNEMONIC: Precedência igual à da matemática: `*` é potência, concatenação é multiplicação, `|` é soma. Como 2 + 3·4², `a|bc*` = `a|(b(c*))`.
DESTAQUE MNEMONIC: `*` = zero ou mais (a estrela é generosa: aceita até nada). `+` = um ou mais (MAIS = pelo menos um). `?` = talvez (zero ou um).

TEXTO: **Palácio da memória**: ainda na Floresta Léxica, o **Trem do Autômato**. A Lexi desenha o trajeto (ER), os duendes de Thompson espalham trilhos ε por todo lado (AFN), e o maquinista junta estações em cestos (subconjuntos) para nunca ficar em dúvida (AFD).
DESTAQUE WATCH_OUT: Confusões clássicas: (1) achar que AFN é mais poderoso que AFD, reconhecem as mesmas linguagens; (2) esquecer o ε-fecho depois do move; (3) achar que ER sabe contar (aⁿbⁿ não é regular!).

=== AULA DE LEITURA [STORY] A turma no grupo do WhatsApp

=== AULA DE LEITURA [FORMAL] Construção de subconjuntos: definição de prova
TEXTO: **AFN**: N = (S, Σ, δ, s₀, F), com δ: S × (Σ ∪ {ε}) → P(S). **AFD**: caso particular sem transições ε e com exatamente um destino para cada par (estado, símbolo).
TEXTO: **ε-fecho(s)**: estados alcançáveis a partir de s usando apenas transições ε (inclui s). **ε-fecho(T)** = ∪ ε-fecho(s), s ∈ T. **move(T, a)**: estados alcançáveis a partir de algum s ∈ T por UMA transição rotulada a.
CODIGO (Cálculo do ε-fecho (Livro do Dragão, Fig. 3.33)):
    ε-fecho(T):
        empilhe todos os estados de T
        fecho ← T
        enquanto a pilha não estiver vazia:
            desempilhe t
            para cada u com t --ε--> u:
                se u ∉ fecho: fecho ← fecho ∪ {u}; empilhe u
        devolva fecho
CODIGO (Construção de subconjuntos (Algoritmo 3.20)):
    Dstates ← { ε-fecho({s₀}) }, não marcado
    enquanto houver T não marcado em Dstates:
        marque T
        para cada símbolo a ∈ Σ:
            U ← ε-fecho(move(T, a))
            se U ∉ Dstates: adicione U (não marcado)
            Dtran[T, a] ← U
    estado inicial do AFD: ε-fecho({s₀})
    estados finais do AFD: todo T com T ∩ F ≠ ∅
TEXTO: **Correção**: o AFD D simula todos os caminhos do AFN N em paralelo; após ler w, D está em T exatamente quando T é o conjunto de estados em que N pode estar após ler w. Logo L(D) = L(N).
CODIGO (Exemplo do livro: AFN de Thompson de (a|b)*abb (estados 0..10, final 10)):
    A = {0,1,2,4,7}
    B = {1,2,3,4,6,7,8}
    C = {1,2,4,5,6,7}
    D = {1,2,4,5,6,7,9}
    E = {1,2,4,5,6,7,10}
    
    Dtran   a   b
    →A      B   C
     B      B   D
     C      B   C
     D      B   E
    *E      B   C
PREVEJA: No exemplo do livro, por que E é o único estado final?
    (     ) Porque foi o último criado
    (certa) Porque é o único que contém o estado 10, final do AFN
    (     ) Porque tem mais estados
    (     ) Porque Dtran[E, b] = C
    EXPLICACAO: Regra: T é final se T ∩ F ≠ ∅. F = {10} e só E contém o 10.
DESTAQUE NO_DUMB_QUESTIONS: P: O AFD do livro tem 5 estados, mas o AFD mínimo de (a|b)*abb tem 4. Está errado? R: Não! A construção de subconjuntos não garante o mínimo. A e C se comportam igual (ambos vão para B com a e para C com b) e a minimização os funde.
WIDGET DFA gramatica= entrada=(a|b)*abb legenda=O motor mostra o AFD já minimizado: 4 estados.
TEXTO: **Custo**: um AFN de n estados pode gerar um AFD de até 2ⁿ estados. Comparação clássica para reconhecer x com a ER r: simular o AFN gasta espaço O(|r|) e tempo O(|r| × |x|); o AFD gasta tempo O(|x|), mas pode exigir espaço O(2^|r|) no pior caso.
PREVEJA: Qual afirmação é VERDADEIRA?
    (     ) AFN reconhece mais linguagens que AFD
    (certa) Todo AFN tem um AFD equivalente, que pode ter exponencialmente mais estados
    (     ) A construção de subconjuntos sempre produz o AFD mínimo
    (     ) O estado inicial do AFD é sempre {s₀}
    EXPLICACAO: Mesmo poder (linguagens regulares), custo de tamanho possivelmente exponencial. O inicial é ε-fecho({s₀}), que pode ser maior que {s₀}.
DESTAQUE EXAM_TIP: Questão clássica: 'converta o AFN de Thompson de (a|b)*abb em AFD'. Decore o caminho: ε-fecho({0}) = {0,1,2,4,7}, cinco estados A–E, E final, e A ≡ C na minimização. Escreva Dtran[T, a] = ε-fecho(move(T, a)) no topo da folha.
REVELAR: Escreva a fórmula central do algoritmo e as regras de inicial e finais.
    RESPOSTA: Dtran[T, a] = ε-fecho(move(T, a)). Inicial: ε-fecho({s₀}). Finais: todo T que contém pelo menos um estado final do AFN.

=== AULA DE LEITURA [MNEMONIC] Anda e Fecha a Porta
DESTAQUE MNEMONIC: **Anda e fecha a porta!** Primeiro ANDA com a letra (move), depois FECHA (ε-fecho). Como a sua mãe gritando da cozinha: entrou, fecha a porta!
DESTAQUE MNEMONIC: **Cesto de frutas**: cada estado do AFD é um cesto com estados do AFN dentro. O cesto é **final se tem UMA fruta premiada** (um final do AFN). O **cesto vazio ∅** é o estado morto.
TEXTO: **Palácio da memória**: na Floresta Léxica, logo depois do Trem do Autômato, fica a **Fábrica de Subconjuntos** . Os duendes de Thompson entregam trilhos bagunçados (AFN); os operários põem estados em cestos, carimbam A, B, C… e entregam ao trem um mapa sem dúvidas (AFD).
DESTAQUE MNEMONIC: **2ⁿ = interruptores**: cada estado do AFN é uma lâmpada que está acesa (no cesto) ou apagada. n lâmpadas → 2ⁿ combinações. É o TETO, não o normal.
PREVEJA: Qual a ordem correta dentro de cada passo da construção?
    (     ) ε-fecho, depois move
    (certa) move, depois ε-fecho
    (     ) só move
    (     ) só ε-fecho
    EXPLICACAO: Anda (move com a letra) e fecha a porta (ε-fecho). O ε-fecho 'sozinho' só aparece uma vez: no estado inicial, ε-fecho({s₀}).
DESTAQUE MNEMONIC: **Inicial também fecha a porta**: o estado inicial do AFD NÃO é {s₀}, é ε-fecho({s₀}). Se esqueceu, o cesto começa faltando fruta.
WIDGET NFA_SUBSET gramatica= entrada=eps legenda=a*b*: o inicial já é {0, 1} por causa do ε. Repare que A já é final, a cadeia vazia é aceita!
DESTAQUE WATCH_OUT: Contrastes que caem na prova: **move** usa UMA letra; **ε-fecho** não usa letra nenhuma. **AFN** pode estar em vários estados; **AFD** em exatamente um. **∅** é o estado morto, não o inicial. Subconjuntos NÃO minimiza: isso é outra etapa.
DESTAQUE MNEMONIC: A esteira completa: **T**hompson **T**ransforma (ER → AFN), **S**ubconjuntos **S**implificam (AFN → AFD), **M**inimização **M**ata os repetidos (AFD → AFD mínimo). Lex/Flex rodam a esteira inteira por você.
REVELAR: Sem olhar: as 3 regras da construção de subconjuntos.
    RESPOSTA: 1) Inicial = ε-fecho({s₀}). 2) Dtran[T, a] = ε-fecho(move(T, a)), anda e fecha a porta. 3) T é final se contém algum final do AFN.
REVELAR: Por que analisadores léxicos preferem AFD?
    RESPOSTA: Um passo por caractere, sem voltar atrás e sem carregar conjuntos. A conversão (talvez cara) é feita uma vez só, quando o léxico é gerado.

################ ASSUNTO DFA_MINIMIZATION: Minimização de AFD (tabela de pares)  prereqs=[REGEX_DFA]
FICHA: Minimizar um AFD é fundir os estados equivalentes (que nenhuma cadeia consegue distinguir): marca-se todo par final × não-final, propaga-se a marca pelas transições até estabilizar, e os pares que sobram sem marca viram um estado só, o AFD mínimo, único a menos de nomes.
  gancho: MPJ: Marca, Propaga, Junta. O morto também vota.
  termos: [equivalen, distingu, par, marca, final, morto, tabela]
  erros comuns: [Esquecer de completar o AFD com o estado morto antes de montar a tabela, Marcar um par com base num par de destino que ainda NÃO está marcado, Parar depois de uma rodada, sem repetir até nada mudar, Esquecer de remover estados inalcançáveis, Fazer a tabela e não desenhar o AFD mínimo (com inicial e finais) no fim]
  FLASH: Quando dois estados são equivalentes? -> Quando nenhuma cadeia w leva um a final e o outro a não-final
  FLASH: O que a rodada 1 marca? -> Todo par (final, não-final), a testemunha é a cadeia vazia
  FLASH: Regra das rodadas seguintes? -> Marque {p,q} se, para alguma letra c, {δ(p,c), δ(q,c)} já está marcado
  FLASH: Quando parar? -> Quando uma rodada inteira não marca nenhum par novo
  FLASH: O que fazer se falta transição? -> Completar com o estado morto ∅ (não final, laço em tudo)
  FLASH: Quantas casas tem a tabela com n estados? -> n(n−1)/2 (só a escadinha de baixo)
  FLASH: No AFD do livro para (a|b)*abb, quem se funde? -> q0 e q2 (A e C): 5 estados viram 4
  FLASH: Método alternativo à tabela? -> Refinar partições (Moore/Hopcroft): começa com {F, S−F} e divide grupos
  FLASH: O AFD mínimo é único? -> Sim, a menos de renomear os estados (Myhill–Nerode)

=== AULA DE LEITURA [FORMAL] Minimização: definição de prova
TEXTO: Seja D = (S, Σ, δ, s₀, F) um AFD **completo** e com todos os estados alcançáveis. Estenda δ para cadeias: δ*(p, ε) = p e δ*(p, xw) = δ*(δ(p, x), w).
TEXTO: **Equivalência**: p ≡ q se, para toda w ∈ Σ*, δ*(p, w) ∈ F ⇔ δ*(q, w) ∈ F. Caso contrário, p e q são **distinguíveis**, e uma w que os separa é uma **testemunha**. ≡ é uma relação de equivalência; suas classes são os estados do AFD mínimo.
CODIGO (Algoritmo de preenchimento da tabela (pares distinguíveis)):
    MinimizaPorTabela(D):
        remova os estados inalcançáveis a partir de s₀
        se faltar transição: adicione ∅ (não final, δ(∅, c) = ∅) e complete
        para cada par {p, q}:
            se (p ∈ F) ≠ (q ∈ F): marque {p, q}
        repita
            para cada par {p, q} não marcado:
                se existe c ∈ Σ com {δ(p,c), δ(q,c)} marcado:
                    marque {p, q}
        até nenhuma marcação nova
        pares não marcados ⇒ p ≡ q; junte cada classe num estado
TEXTO: **Construção do mínimo**: estados = classes [p]; δ'([p], c) = [δ(p, c)] (bem definido, porque estados equivalentes vão para estados equivalentes); inicial = [s₀]; finais = classes contidas em F. Se [∅] tiver só o ∅, pode ser omitido do desenho.
CODIGO (Alternativa: refinar partições (o caminho do Livro do Dragão, Alg. 3.39)):
    MinimizaPorPartições(D):        // Moore; Hopcroft é a versão otimizada
        Π ← { F, S − F }
        repita
            para cada grupo G de Π:
                divida G: p e q ficam juntos se, para todo c,
                δ(p,c) e δ(q,c) caem no MESMO grupo de Π
        até Π não mudar
PASSOS Partições no AFD do livro ((a|b)*abb):
    1. Π₀ = { {q0,q1,q2,q3}, {q4} }
    2. Com 'b', q3 vai para {q4} e os outros ficam no grupo grande: Π₁ = { {q0,q1,q2}, {q3}, {q4} }
    3. Com 'b', q1 vai para {q3} e q0, q2 vão para o grupo grande: Π₂ = { {q0,q2}, {q1}, {q3}, {q4} }
    4. q0 e q2 têm destinos idênticos: Π não muda mais. Mesmo resultado da tabela: q0 ≡ q2.
TEXTO: **Teorema (Myhill–Nerode)**: para cada linguagem regular existe um AFD com o número mínimo de estados, e ele é **único a menos de renomear os estados**. Por isso dois alunos que minimizam certo chegam ao mesmo autômato, só com nomes diferentes.
PREVEJA: Qual afirmação é FALSA?
    (     ) O AFD mínimo é único a menos de nomes
    (     ) A tabela e as partições dão o mesmo AFD mínimo
    (certa) Um par que ficou sem marca numa rodada nunca mais pode ser marcado
    (     ) Estados inalcançáveis devem ser removidos antes
    EXPLICACAO: Falso: no AFD do livro, {q0,q1} fica em branco na rodada 2 e é marcado na rodada 3. Só no FIM (quando uma rodada inteira não marca nada) o branco vira veredito de equivalência.
TEXTO: **Custo**: a tabela tem n(n − 1)/2 casas e cada rodada as varre todas: polinomial, ótimo para provas com até ~8 estados. O algoritmo de Hopcroft faz o mesmo em O(n · |Σ| · log n) e é o que geradores de léxico usam.
DESTAQUE EXAM_TIP: Roteiro de prova: (1) inalcançáveis fora; (2) completar com ∅; (3) tabela em escadinha com a RODADA em cada casa; (4) repetir até estabilizar; (5) listar as classes; (6) desenhar o AFD mínimo com inicial e finais. Esquecer o passo 6 é perder metade da questão.
REVELAR: Defina estados distinguíveis e diga o que a rodada 1 marca.
    RESPOSTA: p e q são distinguíveis se existe w com δ*(p, w) ∈ F e δ*(q, w) ∉ F (ou vice-versa). A rodada 1 marca todo par final × não-final, cuja testemunha é ε.

=== AULA DE LEITURA [MNEMONIC] Marca, Propaga, Junta
DESTAQUE MNEMONIC: **MPJ: Marca, Propaga, Junta.** MARCA final × não-final. PROPAGA as marcas pelas setas, rodada após rodada. JUNTA quem sobrou sem marca. (Pense em 'MPJ = Ministério Público Julgando quem é igual'.)
TEXTO: **Palácio da memória**: na Floresta Léxica, logo depois da Fábrica de Subconjuntos, fica a **Tabela dos Pares** : uma escada de pedra. Cada degrau tem casinhas, uma para cada par de estados. O guarda pinta de vermelho as casinhas dos pares diferentes; as que ficam brancas viram uma casa só.
DESTAQUE MNEMONIC: **Escadinha, não quadrado.** {p,q} = {q,p} e {p,p} não interessa: desenhe só o triângulo de baixo. n estados → n(n−1)/2 casas. Com 5 estados: 10 casas.
DESTAQUE MNEMONIC: **Final e não-final são água e óleo**: não se misturam nunca. Por isso a rodada 1 é automática.
DESTAQUE MNEMONIC: **Dominó**: 'se os FILHOS são diferentes, os PAIS também são'. Se p e q, com a mesma letra, caem em casinha vermelha, pinte {p,q} de vermelho.
PREVEJA: Na rodada 2, o par {q0,q1} vai com 'b' para {q2,q3}, que está em branco AGORA. O que fazer?
    (     ) Marcar, porque provavelmente vai ser marcado
    (certa) Deixar em branco e voltar na próxima rodada
    (     ) Fundir q0 e q1
    EXPLICACAO: Dominó só cai empurrado por peça que JÁ caiu. Na rodada 3, {q2,q3} está vermelho e aí {q0,q1} cai também.
DESTAQUE MNEMONIC: **O morto também vota.** O estado ∅ não fala, não aceita nada, mas DISTINGUE: sem ele, a*b* viraria (a|b)*. Antes de desenhar a escadinha, pergunte: 'falta alguma seta?'
DESTAQUE WATCH_OUT: Os três tropeços clássicos: (1) **esquecer o ∅**; (2) **marcar com base em casinha ainda branca**; (3) **parar depois de uma rodada só**, sem conferir se o dominó continua.
DESTAQUE MNEMONIC: A esteira da Floresta: **T**hompson **T**ransforma (ER → AFN), **S**ubconjuntos **S**implificam (AFN → AFD), **M**inimização **M**ata os repetidos (AFD → AFD mínimo). E o mínimo é **único**: 'cada linguagem tem uma única certidão de nascimento mínima'.
WIDGET MINIMIZE gramatica= entrada=0 legenda=Recite MPJ enquanto o widget roda: marca (rodada 1), propaga (rodadas 2 e 3), junta (q0 com q2).
REVELAR: Sem olhar: os 3 passos e os 3 tropeços.
    RESPOSTA: Passos: Marca final × não-final; Propaga pelas setas até estabilizar; Junta os pares em branco. Tropeços: esquecer o estado morto, marcar com base em par ainda não marcado, e não repetir as rodadas.
REVELAR: Contraste: o que a construção de subconjuntos faz e o que a minimização faz?

=== AULA DE LEITURA [STORY] A triagem dos Correios
[NARRADOR] Centro de triagem dos Correios, madrugada. Uma esteira infinita de caracteres passa na frente de um robô. A Lexi segura uma folha plastificada cheia de regras.
[LEXI] Eu não separo nada na mão. Eu escrevo a FOLHA DE REGRAS, entrego para a fábrica, e a fábrica monta o robô que faz a triagem sozinho.
PASSOS Correios → Lex/Flex:
    1. A folha de regras ('pacote assim → carimbo tal') é o **arquivo .l**: cada linha é um **padrão** (expressão regular) e uma **ação** em C.
    2. A fábrica que lê a folha e monta o robô é o programa **lex** (ou **flex**): ele gera o arquivo **lex.yy.c**.
    3. O robô é a função **yylex()**: cada vez que alguém chama, ela pega o próximo pacote e devolve o carimbo.
    4. O pacote que o robô pegou é o **lexema**: fica em **yytext**, e o tamanho dele em **yyleng**.
    5. O carimbo é o **return TOKEN;** da ação. Ação vazia **{ }** é a lixeira: espaço e comentário somem.
[PROF] O robô obedece a DUAS regras de ouro. Primeira: ele é **guloso**: sempre pega o MAIOR pacote que alguma regra aceita. Segunda: se duas regras aceitam pacotes do mesmo tamanho, vence a que está **mais acima na folha**.

PREVEJA: Com essa folha ("if" acima da regra de identificador), o que vira 'iffy'?
    (     ) IF seguido de ID 'fy'
    (certa) Um único ID 'iffy'
    (     ) Erro léxico
    (     ) IF, IF, ID
    EXPLICACAO: Guloso! A regra de ID aceita 4 caracteres; a do "if" só 2. O maior pacote vence, e a ordem nem chega a ser consultada.
[BYTE] E se alguém colar a regra de ID ACIMA da regra do "if"?
WIDGET FLEX gramatica=%% ; [ \t\n]+                { } ; [a-z][a-z0-9]*          { return ID; } ; "if"                    { return IF; } ; [0-9]+                  { return NUM; } ; %% entrada=if x 10 legenda=Folha com a ordem trocada: olhe o que aconteceu com o 'if'.
REVELAR: Por que 'if' virou ID?
    RESPOSTA: Empate: as duas regras aceitam 'if' com 2 caracteres. No empate vence a que vem PRIMEIRO, e agora é a de ID. Palavras-chave SEMPRE vêm antes da regra de identificador.

    RESPOSTA: Arquivo .l, o programa lex/flex, a função yylex() gerada em lex.yy.c, o lexema (yytext) e o token devolvido pelo return.

=== AULA DE LEITURA [WORKED] Escrevendo o scanner.l do TP
[PROF] Vamos montar com calma um arquivo .l completo, do jeito que você entrega no trabalho prático. Ele compila sozinho, sem Bison.
CODIGO (scanner.l: compile com: lex scanner.l && gcc lex.yy.c && ./a.out < teste.txt):
    %{
    /* scanner.l : analisador lexico do TP */
    #include <stdio.h>
    enum { INT = 1, FLOAT, IF, ELSE, ID, NUM, REAL,
           LE, LT, ATRIB, MAIS, PV, ABRE, FECHA };
    int linha = 1;
    %}
    DIGITO   [0-9]
    LETRA    [a-zA-Z_]
    %%
    [ \t]+                       { /* ignora espacos */ }
    \n                           { linha++; }
    "//".*                       { /* ignora comentario */ }
    "int"                        { return INT; }
    "float"                      { return FLOAT; }
    "if"                         { return IF; }
    "else"                       { return ELSE; }
    {LETRA}({LETRA}|{DIGITO})*   { return ID; }
    {DIGITO}+"."{DIGITO}+        { return REAL; }
    {DIGITO}+                    { return NUM; }
    "<="                         { return LE; }
    "<"                          { return LT; }
    "="                          { return ATRIB; }
    "+"                          { return MAIS; }
    ";"                          { return PV; }
    "("                          { return ABRE; }
    ")"                          { return FECHA; }
    .                            { printf("Erro lexico na linha %d: '%s'\n", linha, yytext); }
    %%
    int yywrap(void) { return 1; }
    
    int main(void) {
        int t;
        while ((t = yylex()) != 0)
            printf("linha %d: token %d, lexema '%s' (%d chars)\n",
                   linha, t, yytext, yyleng);
        return 0;
    }
PASSOS Lendo o arquivo, parte por parte:
    1. **%{ … %}**: código C copiado literalmente para o topo de lex.yy.c, includes, a enumeração dos tokens e o contador de linha.
    2. **DIGITO [0-9]** e **LETRA [a-zA-Z_]**: definições nomeadas. Nas regras, usamos {DIGITO} e {LETRA} como apelidos.
    3. Primeiro **%%**: começam as regras. Cada linha: padrão, espaço, ação entre chaves.
    4. Espaços e comentários: ação sem return → são descartados. O **\n** só soma 1 em `linha`.
    5. Palavras-chave ("int", "float", "if", "else") ANTES da regra de identificador: ganham o empate.
    6. REAL antes de NUM por clareza (o maior casamento já resolveria). "<=" antes de "<", também por clareza.
    7. A regra **.** por último: qualquer caractere que sobrou é erro léxico, com o número da linha.
    8. Segundo **%%**: código C do usuário. **yywrap** devolvendo 1 avisa que não há outro arquivo; o **main** chama yylex() até ela devolver 0 (fim da entrada).
TEXTO: Agora vamos 'rodar de cabeça' a linha `float media = 3.14; // comentario`.
PASSOS Resolvido: tokens da linha:
    1. 'float' → empate entre "float" e ID (5 caracteres): vence "float", que vem antes → **FLOAT**.
    2. ' ' → regra de espaços, ação vazia: nada.
    3. 'media' → só ID casa → **ID**, yytext = "media", yyleng = 5.
    4. '=' → **ATRIB**. '3.14' → REAL casa 4 caracteres, NUM só 1 → **REAL**.
    5. ';' → **PV**. '// comentario' → "//".* engole até o fim da linha → nada.
WIDGET FLEX gramatica=%{ ; #include "y.tab.h" ; int linha = 1; ; %} ; %% ; [ \t]+                  { } ; \n                      { linha++; } ; "//".*                  { } ; "int"                   { return INT; } ; "float"                 { return FLOAT; } ; "if"                    { return IF; } ; "else"                  { return ELSE; } ; [a-zA-Z_][a-zA-Z0-9_]*  { yylval.nome = strdup(yytext); return ID; } ; [0-9]+"."[0-9]+         { yylval.real = atof(yytext); return REAL; } ; [0-9]+                  { yylval.inteiro = atoi(yytext); return NUM; } ; "<="                    { return LE; } ; "<"                     { return LT; } ; "="                     { return ATRIB; } ; "+"                     { return MAIS; } ; ";"                     { return PV; } ; "("                     { return ABRE; } ; ")"                     { return FECHA; } ; .                       { printf("Erro lexico na linha %d: '%s'\n", linha, yytext); } ; %% ; int yywrap(void) { return 1; } entrada=float media = 3.14; // comentario legenda=Confira: FLOAT ID ATRIB REAL PV.
TEXTO: Sua vez (exemplo esmaecido), com o mesmo scanner.
REVELAR: Tokens de `intx = 3.5;`?
    RESPOSTA: ID ATRIB REAL PV. 'intx' tem 4 letras: a regra de ID casa mais que a de "int" (3). Guloso!
REVELAR: Tokens de `if (x <= 10) x = x + 1;`?
    RESPOSTA: IF ABRE ID LE NUM FECHA ID ATRIB ID MAIS NUM PV, 12 tokens. '<=' é um token só.
REVELAR: O que acontece com `int x@ = 2;`?
    RESPOSTA: Tokens INT ID ATRIB NUM PV, e o scanner imprime 'Erro lexico na linha 1: '@''. A regra '.' não tem return, então o '@' não vira token e a análise continua.
WIDGET FLEX gramatica=%{ ; #include "y.tab.h" ; int linha = 1; ; %} ; %% ; [ \t]+                  { } ; \n                      { linha++; } ; "//".*                  { } ; "int"                   { return INT; } ; "float"                 { return FLOAT; } ; "if"                    { return IF; } ; "else"                  { return ELSE; } ; [a-zA-Z_][a-zA-Z0-9_]*  { yylval.nome = strdup(yytext); return ID; } ; [0-9]+"."[0-9]+         { yylval.real = atof(yytext); return REAL; } ; [0-9]+                  { yylval.inteiro = atoi(yytext); return NUM; } ; "<="                    { return LE; } ; "<"                     { return LT; } ; "="                     { return ATRIB; } ; "+"                     { return MAIS; } ; ";"                     { return PV; } ; "("                     { return ABRE; } ; ")"                     { return FECHA; } ; .                       { printf("Erro lexico na linha %d: '%s'\n", linha, yytext); } ; %% ; int yywrap(void) { return 1; } entrada=if (x <= 10) x = x + 1; legenda=Confira a segunda resposta (e teste as outras digitando).

REVELAR: Como o Flex consegue achar o MAIOR casamento entre dezenas de regras de uma vez?
    RESPOSTA: Ele junta os AFNs de todas as regras num só (um novo estado inicial com ε para cada um), converte para AFD e roda o AFD até travar no estado morto, lembrando o ÚLTIMO estado final por onde passou. Esse final diz o tamanho do lexema e a regra (a de menor número, em caso de empate).
REVELAR: E por que o resultado é tão rápido?
    RESPOSTA: Porque é um AFD: um passo por caractere, uma consulta na tabela. Toda a dificuldade (subconjuntos, minimização) foi paga quando o lex gerou o lex.yy.c.

=== AULA DE LEITURA [FORMAL] A especificação Lex: definição de prova
TEXTO: Um programa Lex tem três seções separadas por `%%`: **declarações** (código C entre `%{` e `%}` e definições regulares nome → ER), **regras de tradução** na forma `Padrão { Ação }` e **funções auxiliares** em C.
CODIGO (Estrutura de um arquivo .l):
    declarações
    %%
    regras de tradução
    %%
    funções auxiliares
CODIGO (Expressões regulares do Lex (Livro do Dragão, Fig. 3.8)):
    EXPRESSÃO  CASA COM                         EXEMPLO
    c          o caractere c (não operador)     a
    \c         o caractere c literalmente       \*
    "s"        a cadeia s literalmente          "**"
    .          qualquer caractere menos \n      a.*b
    ^          início de linha                  ^abc
    $          fim de linha                     abc$
    [s]        qualquer caractere de s          [abc]
    [^s]       qualquer caractere fora de s     [^abc]
    r*         zero ou mais r                   a*
    r+         um ou mais r                     a+
    r?         zero ou um r                     a?
    r{m,n}     de m a n ocorrências de r        a{1,5}
    r1r2       r1 seguido de r2                 ab
    r1|r2      r1 ou r2                         a|b
    r1/r2      r1, se seguido de r2             abc/123
TEXTO: **Resolução de conflitos** (Dragão, 3.5.3): (1) prefira sempre o **prefixo mais longo** da entrada que casa com algum padrão; (2) se o prefixo mais longo casa com dois ou mais padrões, prefira o **listado primeiro**.
PASSOS Interface do analisador gerado:
    1. **yylex()**: devolve o código do próximo token; devolve 0 no fim da entrada.
    2. **yytext**: ponteiro para o início do lexema reconhecido; **yyleng**: seu comprimento.
    3. **yylval**: variável global com o valor de atributo do token, compartilhada com o analisador sintático (Yacc/Bison).
    4. **yyin**: arquivo de entrada (padrão: stdin). **yywrap()**: chamada no fim do arquivo; devolver 1 significa 'acabou'.
TEXTO: **Implementação**: o Lex constrói um AFN para cada padrão pᵢ, cria um novo estado inicial com transições ε para cada um, e converte o AFN combinado em AFD. Ao ler a entrada, o AFD segue até não haver transição; então recua até o último estado de aceitação visto. Se esse estado contém finais de vários padrões, vale o de menor índice.
PREVEJA: Com as regras `"if" {…}` e `[a-z]+ {…}` nessa ordem, a entrada 'ifa' produz:
    (     ) o token de "if" e depois o lexema 'a'
    (certa) um único lexema 'ifa', da regra [a-z]+
    (     ) erro: conflito
    EXPLICACAO: Regra 1 de resolução: prefixo mais longo. [a-z]+ casa 3 caracteres; "if" casa 2.
PREVEJA: Qual é o papel do operador `/` em `DO/({letra}|{digito})*=…`?
    (     ) Divisão
    (certa) Lookahead: só casa DO se o que vem depois casa com o resto, mas o resto não entra no lexema
    (     ) Comentário
    (     ) Alternativa, como |
    EXPLICACAO: É o operador de contexto à direita (lookahead), usado no exemplo do Fortran, onde DO5I=1.25 é atribuição e DO5I=1,25 é laço.
DESTAQUE EXAM_TIP: Em prova discursiva: cite as 3 seções, as 2 regras de resolução de conflito (mais longo; empate → primeiro) e explique que o Lex gera um AFD a partir das ERs (Thompson + subconjuntos). Bônus: palavras-chave antes de identificadores.
REVELAR: Escreva a regra de um identificador que devolve ID e guarda o nome para o sintático.
    RESPOSTA: [a-zA-Z_][a-zA-Z0-9_]*   { yylval.nome = strdup(yytext); return ID; }, strdup copia, porque yytext será sobrescrito no próximo token.

=== AULA DE LEITURA [MNEMONIC] Guloso, mas educado
DESTAQUE MNEMONIC: **D-R-C**: **D**efinições %% **R**egras %% **C**ódigo. Igualzinho ao Bison: Declara, Regra, Código. Os dois %% são as duas paredes da sala das regras.
DESTAQUE MNEMONIC: O Flex é **guloso, mas educado**: GULOSO porque sempre come o maior pedaço; EDUCADO porque, no empate, respeita a fila, quem chegou primeiro no arquivo é atendido.
DESTAQUE MNEMONIC: **Palavra-chave é VIP**: entra ANTES do ID na folha. Se o ID passar na frente, 'if' vira variável e o seu TP quebra.
TEXTO: **Palácio da memória**: na Floresta Léxica, na beira do rio, fica a **Oficina Flex** . Na porta está pregada a folha D-R-C. Lá dentro, a Lexi alimenta a máquina com expressões regulares e sai pelo outro lado um robô chamado lex.yy.c.
DESTAQUE MNEMONIC: Tudo do lex começa com **yy**: **yytext** = o TEXTO do lexema; **yyleng** = o LENGth (tamanho); **yylval** = o VALor que vai para o Bison; **yylex** = o próprio LEXer; **yywrap** = 'embrulha' (acabou o arquivo?).
DESTAQUE MNEMONIC: **{ } vazio = lixeira.** Sem return, o lexema vai para o lixo e o robô continua. É assim que espaços e comentários somem.
PREVEJA: yytext ou yylval: onde está o texto "42" logo depois de casar `[0-9]+`?
    (certa) yytext
    (     ) yylval
    (     ) yyleng
    (     ) yylex
    EXPLICACAO: yytext é o TEXTO cru. yylval só tem o valor se a SUA ação fizer yylval = atoi(yytext).
WIDGET FLEX gramatica=%% ; [ \t\n]+                { } ; "if"                    { return IF; } ; "while"                 { return WHILE; } ; [a-z][a-z0-9]*          { return ID; } ; [0-9]+                  { return NUM; } ; "=="                    { return EQ; } ; "="                     { return ATRIB; } ; "("                     { return ABRE; } ; ")"                     { return FECHA; } ; ";"                     { return PV; } ; %% entrada=iffy = while2; legenda=Guloso: 'iffy' e 'while2' são IDs. Educado: em 'if' sozinho, a regra de cima ganharia.
DESTAQUE WATCH_OUT: Confusões clássicas: (1) achar que a ordem resolve TUDO, o tamanho vem antes; (2) pôr a regra '.' no começo; (3) esquecer yywrap/noyywrap; (4) devolver o token do espaço em vez de ignorar; (5) confundir lex.l (o que você escreve) com lex.yy.c (o que o lex gera).
DESTAQUE REAL_WORLD: Receita do TP para nunca esquecer: `lex scanner.l` → `gcc lex.yy.c` → `./a.out < teste.txt`. Com Bison: `yacc -d parser.y` gera y.tab.h com os tokens, que o scanner.l inclui no %{ %}.
REVELAR: Recite as duas regras de ouro e o mnemônico das seções.
    RESPOSTA: 1) Maior casamento (guloso). 2) Empate → regra listada primeiro (educado). Seções: D-R-C, Definições %% Regras %% Código.
