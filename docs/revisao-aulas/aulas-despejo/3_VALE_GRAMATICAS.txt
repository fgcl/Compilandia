FICHA: Uma gramática livre de contexto (N, T, P, S) gera sentenças trocando não-terminais pelos lados direitos das produções; a árvore de derivação resume essas trocas.
  gancho: G = (N, T, P, S): Nunca Tire Prova Sem estudar.
  termos: [terminal, não-terminal, produção, símbolo inicial, derivação, árvore]
  erros comuns: [Numa derivação mais à esquerda, trocar um NT que não é o mais à esquerda., Achar que as derivações ⇒lm e ⇒rm geram árvores diferentes., Confundir forma sentencial (pode ter NTs) com sentença (só terminais)., Achar que ε não pode ser folha da árvore.]
  FLASH: Os 4 componentes de uma GLC? -> Não-terminais, terminais, produções, símbolo inicial
  FLASH: O que é uma forma sentencial? -> Qualquer α tal que S ⇒* α
  FLASH: O que é uma sentença? -> Uma forma sentencial só com terminais
  FLASH: Derivação mais à esquerda? -> Sempre substitui o NT mais à esquerda
  FLASH: Quantas derivações ⇒lm tem uma árvore? -> Exatamente uma
  FLASH: Folhas da árvore lidas da esquerda para a direita? -> O produto da árvore: a sentença
  FLASH: Linguagem de S → a S b | ε? -> { aⁿbⁿ | n ≥ 0 }
  FLASH: Por que 'livre de contexto'? -> O lado esquerdo é um único NT, trocado sem olhar o que está em volta

=== AULA ANIMADA [BASICO] Regras de troca  (id=CFG_DERIVATION, ~170s, 22 passos, exemplo começa no passo 4)
1. [BYTE] O parser recebe os tokens do scanner. Ele precisa saber quais sequências de tokens são frases válidas.
     palco: Frase certa ou errada? | n + n | n + +
2. [BYTE] Uma destas frases está mal escrita. Toque nela.
     palco: Frase certa ou errada? | n + n | n + +
     PERGUNTA(toque): certas=[n + +] erradas=[n + n]
       dica: Depois de um mais, precisa vir um número.
       acerto: Isso. Falta um número depois do mais.
3. [BYTE] Listar todas as frases certas não dá: elas são infinitas. E expressão regular não basta, porque não sabe casar parênteses.
     palco: Frase certa ou errada? | n + n | n + + | ...
4. [BYTE] Uma gramática livre de contexto é uma lista curta de regras de troca que gera todas as frases válidas.
     palco: GRAMÁTICA
5. [BYTE] Cada regra, ou produção, diz que o símbolo da esquerda pode ser trocado pelo lado direito. Aqui, E pode virar E mais E, ou pode virar n.
     palco: Gramática | E -> E + E | E -> n
6. [BYTE] E é um não-terminal: ainda vai ser trocado. O mais e o n são terminais: são os tokens, e ficam na frase.
     palco: Gramática | E -> E + E | E -> n | *E
7. [BYTE] Começo pelo símbolo inicial, E, e aplico a primeira regra. Cada troca é um passo de derivação.
     palco: Gramática | *E -> E + E | E -> n | E | + | E
8. [BYTE] Numa derivação mais à esquerda, qual E eu troco agora? Toque nele.
     palco: Gramática | E -> E + E | E -> n | E | + | E
     PERGUNTA(toque): certas=[E] erradas=[E]
       dica: O nome já conta: mais à esquerda.
       acerto: Esse mesmo. Sempre o não-terminal mais à esquerda.
9. [BYTE] Ele vira n. Depois troco o outro, e sobra a frase n mais n.
     palco: Gramática | E -> E + E | *E -> n | n | + | n
10. [BYTE] Só sobraram terminais, então a frase pertence à linguagem da gramática. O desenho dessas trocas é a árvore de derivação.
     palco: Gramática | E -> E + E | E -> n | E | E | n | + | E | n
11. [BYTE] Derivar uma frase tem três passos. Eles ficam aqui na tela.
     palco: Receita | 1. Comece pelo símbolo inicial. | 2. Troque o não-terminal mais à esquerda. | 3. Repita até sobrar só terminal.
12. [BYTE] Na forma E mais E, qual passo escolhe o E da esquerda? Toque.
     palco: Receita | 1. Comece pelo símbolo inicial. | 2. Troque o não-terminal mais à esquerda. | 3. Repita até sobrar só terminal. | E + E
     PERGUNTA(toque): certas=[2. Troque o não-terminal mais à esquerda.] erradas=[1. Comece pelo símbolo inicial., 3. Repita até sobrar só terminal.]
       dica: Um dos passos diz qual não-terminal trocar.
       acerto: Isso. Passo dois: sempre o mais à esquerda.
13. [BYTE] Agora quem deriva é você. A meta é a declaração lá em cima.
     palco: float * id ; | Decl -> Tipo Var ; | Tipo -> int | float | Var -> id | * id | Decl
14. [BYTE] Decl virou Tipo, Var e ponto e vírgula. Qual você troca agora?
     palco: float * id ; | *Decl -> Tipo Var ; | Tipo -> int | float | Var -> id | * id | Tipo | Var | ;
     PERGUNTA(toque): certas=[Tipo] erradas=[Var, ;]
       dica: Passo dois: o não-terminal mais à esquerda.
       acerto: Isso. Tipo vem primeiro.
15. [BYTE] Qual regra de Tipo leva até a meta? Toque nela.
     palco: float * id ; | Decl -> Tipo Var ; | *Tipo -> int | float | Var -> id | * id | *Tipo | Var | ; | Tipo -> int | Tipo -> float
     PERGUNTA(toque): certas=[Tipo -> float] erradas=[Tipo -> int]
       dica: Olhe a primeira palavra da meta.
       acerto: Isso. Tipo vira float.
16. [BYTE] Falta Var. Na meta, um asterisco vem antes do id. Toque na regra.
     palco: float * id ; | Decl -> Tipo Var ; | Tipo -> int | float | *Var -> id | * id | Var -> id | Var -> * id | float | *Var | ;
     PERGUNTA(toque): certas=[Var -> * id] erradas=[Var -> id]
       dica: Só uma regra de Var começa com asterisco.
       acerto: Isso. Sobrou só terminal, e é a meta.
17. [BYTE] Três trocas, uma por vez. Esta é a árvore da declaração.
     palco: float * id ; | Decl -> Tipo Var ; | Tipo -> int | float | Var -> id | * id | Decl | Tipo | float | Var | * | id | ;
18. [BYTE] E a frase int id id ponto e vírgula? Ela está na linguagem?
     palco: float * id ; | Decl -> Tipo Var ; | Tipo -> int | float | Var -> id | * id | int id id ; | Sim | Não
     PERGUNTA(toque): certas=[Não] erradas=[Sim]
       dica: Procure uma regra que ponha dois id seguidos.
       acerto: Isso. Nenhuma regra põe dois id seguidos.
19. [PROF] Sem derivação que chegue nela, a frase fica fora da linguagem. É assim que o parser acusa erro de sintaxe.
     palco: float * id ; | Decl -> Tipo Var ; | Tipo -> int | float | Var -> id | * id | int id id ;
20. [BYTE] Um colega descreveu assim a derivação mais à esquerda. Certo ou errado? Toque.
     palco: Erros comuns | Na derivação mais à esquerda, posso trocar qualquer não-terminal em cada passo. | certo | errado
     PERGUNTA(toque): certas=[errado] erradas=[certo]
       dica: O nome diz qual não-terminal é trocado.
       acerto: Isso. Em cada passo, troca-se sempre o não-terminal mais à esquerda. Na mais à direita, sempre o da direita.
21. [BYTE] Outro erro: tentar trocar um terminal. Terminal é token, não tem regra. Só não-terminal fica do lado esquerdo de uma produção.
     palco: Erros comuns | Certo: Mais à esquerda: troque sempre o primeiro não-terminal da forma. | *Errado: Trocar um terminal por uma regra. | *Certo: Só não-terminal fica do lado esquerdo. Terminal é token e não muda.
22. [BYTE] Resumindo: a gramática livre de contexto gera as frases por trocas. Derivar é aplicar produções a partir do símbolo inicial, e a árvore registra essas trocas.
     palco: Resumo | Gramática: terminais, não-terminais, produções e um símbolo inicial. | Derivar: começar no inicial e trocar não-terminais até sobrar só terminal. | A frase está na linguagem se existe uma derivação para ela.

=== AULA DE LEITURA [STORY] Análise sintática você já fez na escola
[PROF] Lembra da aula de português? Sujeito, predicado, objeto direto… Aquilo se chamava **análise sintática**. Literalmente o mesmo nome!
[BYTE] Sério?! Eu odiava aquilo.
[PROF] Então vamos odiar juntos, mas entendendo. Uma frase é feita de partes, e cada parte tem uma regra de montagem.
CODIGO (Uma minigramática do português):
    Frase -> SN SV
    SN -> Art Sub
    SV -> Ver SN
    Art -> o | a
    Sub -> gato | menina | peixe
    Ver -> come | ama
TEXTO: Cada linha é uma **produção**: 'uma Frase é um sintagma nominal (SN) seguido de um sintagma verbal (SV)'. Quem aparece à esquerda da seta é **não-terminal** (uma categoria). As palavras de verdade, o, gato, come, são **terminais**.
WIDGET DERIVATION gramatica=Frase -> SN SV ; SN -> Art Sub ; SV -> Ver SN ; Art -> o | a ; Sub -> gato | menina | peixe ; Ver -> come | ama entrada=o gato come o peixe legenda=Veja a frase nascer, trocando sempre o não-terminal mais à esquerda.
[PROF] Cada passo troca UM não-terminal pelo lado direito de uma de suas produções. Isso é uma **derivação**. Quando sempre trocamos o mais à esquerda, é uma **derivação mais à esquerda**.
PREVEJA: Essa gramática gera 'a menina ama o gato'?
    (certa) Sim
    (     ) Não
    EXPLICACAO: Frase ⇒ SN SV ⇒ Art Sub SV ⇒ a Sub SV ⇒ a menina SV ⇒ a menina Ver SN ⇒ … ⇒ a menina ama o gato. (Ela não liga para concordância de gênero: 'a gato' também sai. Gramática de brinquedo!)
PREVEJA: E 'gato o come peixe o'?
    (     ) Sim
    (certa) Não
    EXPLICACAO: Todas as palavras existem (léxico ok!), mas a ordem não segue as regras: erro sintático.
TEXTO: Troque palavras por tokens e é igualzinho: `E -> E + T` diz 'uma expressão pode ser uma expressão, um +, e um termo'. O compilador faz análise sintática como você fazia na escola, só que sem preguiça.
DESTAQUE NO_DUMB_QUESTIONS: P: Por que 'livre de contexto'? R: Porque o lado esquerdo é UM não-terminal sozinho: você pode trocar SN por 'Art Sub' em qualquer lugar, não importa o que esteja em volta (o contexto).
DESTAQUE FIRESIDE: Expressão regular: 'Eu descrevo palavras.' Gramática: 'Eu descrevo frases, e sei aninhar coisas, como parênteses dentro de parênteses, coisa que você não consegue!'
REVELAR: Nessa gramática, quem são os terminais e os não-terminais?
    RESPOSTA: Não-terminais: Frase, SN, SV, Art, Sub, Ver. Terminais: o, a, gato, menina, peixe, come, ama. Símbolo inicial: Frase (o da primeira linha).

=== AULA DE LEITURA [VISUAL] Derivação em câmera lenta
[PROF] Vamos ver a gramática de expressões do Livro do Dragão gerando `id + id * id`.
CODIGO (E = expressão, T = termo, F = fator):
    E -> E + T | T
    T -> T * F | F
    F -> ( E ) | id
WIDGET DERIVATION gramatica=E -> E + T | T ; T -> T * F | F ; F -> ( E ) | id entrada=id + id * id legenda=Avance passo a passo e veja a árvore crescer a cada troca.
TEXTO: Em cada linha, o não-terminal trocado é o MAIS À ESQUERDA. As formas intermediárias, como `id + T * F`, se chamam **formas sentenciais**. A última, só com terminais, é uma **sentença**.
PREVEJA: Na derivação mais à esquerda, depois de `id + T`, qual é o próximo passo?
    (certa) id + T * F
    (     ) id + F
    (     ) id + id
    EXPLICACAO: Ainda precisamos gerar `id * id` depois do +. Se T virasse F direto, o `*` nunca apareceria! Então T → T * F.
[BYTE] E a árvore? É a mesma coisa que a derivação?
[PROF] A árvore é o 'resumo' da derivação: mostra QUAL produção foi usada em cada nó, mas esquece a ORDEM das trocas.
WIDGET PARSE_TREE gramatica=E -> E + T | T ; T -> T * F | F ; F -> ( E ) | id entrada=id + id * id legenda=Leia as folhas da esquerda para a direita: dá a sentença.
WIDGET DERIVATION gramatica=S -> a S b | ε entrada=a a a b b b legenda=S -> a S b | ε: cada passo põe um a na frente e um b atrás. Nenhuma ER faz isso!
REVELAR: Quantos passos teve a derivação de `a a a b b b`? Por quê?
    RESPOSTA: 4 passos: três vezes S → a S b e uma vez S → ε. Cada a ganha o seu b casado.
WIDGET DERIVATION gramatica=S -> ( S ) S | ε entrada=( ( ) ) ( ) legenda=Parênteses balanceados. Repare como o ε faz S sumir.
REVELAR: Diferença entre forma sentencial e sentença?
    RESPOSTA: Forma sentencial: qualquer coisa derivável do símbolo inicial (pode ter não-terminais). Sentença: forma sentencial só com terminais.

=== AULA DE LEITURA [WORKED] Derivando à esquerda e à direita
[PROF] Exercício: derivação mais à esquerda E mais à direita de `id + id * id`.
CODIGO ():
    E -> E + T | T
    T -> T * F | F
    F -> ( E ) | id
PASSOS Mais à esquerda (⇒lm): troque sempre o NT mais à esquerda:
    1. E ⇒ E + T
    2. ⇒ T + T
    3. ⇒ F + T
    4. ⇒ id + T
    5. ⇒ id + T * F
    6. ⇒ id + F * F
    7. ⇒ id + id * F
    8. ⇒ id + id * id ✔ (8 passos)
TEXTO: Agora mais à direita (⇒rm): troque sempre o NT mais à DIREITA. Eu começo:
CODIGO ():
    E ⇒ E + T
      ⇒ E + T * F
      ⇒ E + T * id
REVELAR: Próximos dois passos?
    RESPOSTA: ⇒ E + F * id ⇒ E + id * id
REVELAR: E os três passos finais?
    RESPOSTA: ⇒ T + id * id ⇒ F + id * id ⇒ id + id * id
DESTAQUE NO_DUMB_QUESTIONS: P: As duas derivações dão árvores diferentes? R: Não! Mesmas produções, mesma árvore, só muda a ordem das trocas. Cada árvore tem exatamente UMA derivação mais à esquerda e UMA mais à direita.
WIDGET PARSE_TREE gramatica=E -> E + T | T ; T -> T * F | F ; F -> ( E ) | id entrada=id + id * id legenda=A árvore comum às duas derivações.
TEXTO: Mais um, esmaecido: gramática `S -> a S b | ε`, cadeia `a a b b`.
REVELAR: Derivação completa?
    RESPOSTA: S ⇒ a S b ⇒ a a S b b ⇒ a a b b (S → ε no último passo). Com um só NT em cada forma sentencial, mais à esquerda = mais à direita!
WIDGET DERIVATION gramatica=S -> a S b | ε entrada=a a b b legenda=Confira.
DESTAQUE EXAM_TIP: Em prova, escreva um passo por linha, marque o NT trocado e indique ⇒lm ou ⇒rm. Conferência rápida: nº de passos = nº de nós internos da árvore.

=== AULA DE LEITURA [SOCRATIC] O que uma gramática gera?
[PROF] Pergunta 1: tente sem medo.
CODIGO ():
    S -> a S b | ε
PREVEJA: Essa gramática gera `a a b`?
    (     ) Sim
    (certa) Não
    EXPLICACAO: Toda vez que S vira a S b, entram um a E um b. A quantidade de a's e b's é sempre igual.
PREVEJA: Qual é a menor cadeia que ela gera?
    (     ) ab
    (     ) a
    (certa) a cadeia vazia ε
    (     ) b
    EXPLICACAO: S → ε direto: zero passos de 'a S b'.
REVELAR: Descreva a linguagem inteira em uma frase.
    RESPOSTA: { aⁿbⁿ | n ≥ 0 }: n a's seguidos de n b's.
PREVEJA: Uma expressão regular consegue descrever aⁿbⁿ?
    (     ) Sim: a*b*
    (certa) Não
    EXPLICACAO: a*b* aceita aab, com contagens diferentes. Nenhuma ER consegue: seria preciso memória ilimitada. Gramáticas livres de contexto são mais poderosas.
[BYTE] Então gramática é tipo uma ER turbinada?
[PROF] Pode pensar assim: toda linguagem regular é livre de contexto, mas não o contrário. Pergunta 2:
CODIGO ():
    E -> E + T | T
    T -> T * F | F
    F -> ( E ) | id
PREVEJA: Quantos não-terminais essa gramática tem?
    (certa) 3
    (     ) 5
    (     ) 8
    EXPLICACAO: E, T e F: os que aparecem do lado esquerdo.
PREVEJA: E quantos terminais?
    (     ) 3
    (certa) 5
    (     ) 8
    EXPLICACAO: +, *, (, ) e id.
REVELAR: Por que numa derivação precisamos escolher QUAL não-terminal trocar?
    RESPOSTA: Porque uma forma sentencial pode ter vários NTs. Fixar uma ordem (sempre o mais à esquerda, ou sempre o mais à direita) deixa a derivação única para cada árvore. Os analisadores LL constroem a mais à esquerda; os LR, a mais à direita ao contrário.
WIDGET DERIVATION gramatica=E -> E + T | T ; T -> T * F | F ; F -> ( E ) | id entrada=( id ) * id legenda=Derive você mesmo antes de avançar.

=== AULA DE LEITURA [FORMAL] GLC e derivações: definição formal
TEXTO: **Gramática livre de contexto** G = (N, T, P, S): N, conjunto de não-terminais (variáveis sintáticas); T, conjunto de terminais (os tokens); P, conjunto de produções A → α, com A ∈ N e α ∈ (N ∪ T)*; S ∈ N, o símbolo inicial.
TEXTO: **Derivação em um passo**: se A → γ ∈ P, então αAβ ⇒ αγβ. ⇒* significa 'zero ou mais passos'; ⇒⁺, 'um ou mais passos'.
TEXTO: Se S ⇒* α, então α é uma **forma sentencial** de G; se α só tem terminais, é uma **sentença**. A **linguagem gerada** é L(G) = { w ∈ T* | S ⇒⁺ w }.
TEXTO: **Derivação mais à esquerda** (⇒lm): sempre substitui o não-terminal mais à esquerda. **Mais à direita** (⇒rm, ou canônica): sempre o mais à direita.
TEXTO: **Árvore de derivação**: raiz rotulada S; nós internos rotulados por NTs; se um nó A tem filhos X₁…Xₙ, então A → X₁…Xₙ ∈ P; folhas são terminais ou ε. As folhas lidas da esquerda para a direita formam o **produto** (fronteira) da árvore.
CODIGO ():
    Convenções (Livro do Dragão):
      terminais:            a, b, c, +, *, (, ), id, if ...
      não-terminais:        A, B, C, S, E, T, F ...
      símbolos quaisquer:   X, Y, Z
      cadeias de terminais: u, v, w, x, y, z
      formas sentenciais:   α, β, γ
      A → α₁ | α₂ | ... | αₖ   (alternativas de A)
PREVEJA: Se S ⇒* `id + T`, então `id + T` é…
    (     ) uma sentença
    (certa) uma forma sentencial (não sentença)
    (     ) uma produção
    EXPLICACAO: Ainda tem o não-terminal T: é forma sentencial, mas não sentença.
PREVEJA: Cada árvore de derivação corresponde a quantas derivações mais à esquerda?
    (certa) Exatamente uma
    (     ) Várias
    (     ) Nenhuma
    EXPLICACAO: A árvore fixa as produções; a regra 'sempre o mais à esquerda' fixa a ordem. Resultado: uma única derivação ⇒lm.
DESTAQUE EXAM_TIP: Questão tradicional: 'dada G, mostre uma derivação mais à esquerda (ou à direita) de w e a árvore'. Erro que custa pontos: numa ⇒lm, trocar um NT que NÃO é o mais à esquerda.
WIDGET DERIVATION gramatica=E -> E + T | T ; T -> T * F | F ; F -> ( E ) | id entrada=id * ( id + id ) legenda=Pratique: derivação ⇒lm de id * ( id + id ).
REVELAR: Escreva G = (N, T, P, S) para `S -> a S b | ε`.
    RESPOSTA: N = {S}; T = {a, b}; P = {S → a S b, S → ε}; símbolo inicial S.

=== AULA DE LEITURA [MNEMONIC] As quatro peças da gramática
DESTAQUE MNEMONIC: **G = (N, T, P, S)** → '**N**unca **T**ire **P**rova **S**em estudar': Não-terminais, Terminais, Produções, Símbolo inicial.
DESTAQUE MNEMONIC: **Terminal termina**: é folha, não se expande mais. O não-terminal ainda 'não terminou', vai ser trocado.

=== AULA DE LEITURA [FORMAL] Ambiguidade: definição e desambiguação
TEXTO: **Definição.** Uma gramática G é **ambígua** se existe alguma sentença w ∈ L(G) com mais de uma árvore de derivação. Equivalentemente: w tem mais de uma derivação mais à esquerda, ou mais de uma derivação mais à direita.
TEXTO: Uma linguagem é **inerentemente ambígua** se toda GLC que a gera é ambígua. Exemplo: { aⁱbʲcᵏ | i = j ou j = k }.
TEXTO: **Fato.** Não existe algoritmo que decida se uma GLC arbitrária é ambígua (o problema é indecidível).
CODIGO ():
    Desambiguação de expressões (um nível por precedência):
      E → E + T | T        (+ : menor precedência, assoc. à esquerda)
      T → T * F | F        (* : maior precedência, assoc. à esquerda)
      F → ( E ) | id       (átomos)
    Regras:
      operador de MENOR precedência fica mais perto da raiz;
      recursão à ESQUERDA → associatividade à esquerda;
      recursão à DIREITA  → associatividade à direita (ex.: ^).
CODIGO (Else pendurado sem ambiguidade (Livro do Dragão, §4.3.2)):
    stmt → matched_stmt | open_stmt
    matched_stmt → if ( expr ) matched_stmt else matched_stmt | other
    open_stmt → if ( expr ) stmt
              | if ( expr ) matched_stmt else open_stmt
PREVEJA: Para provar que G é ambígua, é suficiente mostrar…
    (     ) uma derivação ⇒lm e outra ⇒rm diferentes para w
    (certa) duas derivações ⇒lm diferentes para a mesma w
    (     ) que G tem recursão à esquerda
    EXPLICACAO: Duas ⇒lm distintas = duas árvores distintas. Uma ⇒lm e uma ⇒rm podem ser da mesma árvore; e recursão à esquerda não tem nada a ver com ambiguidade.
PREVEJA: Toda gramática LL(1) ou LR(1) é…
    (     ) ambígua
    (certa) não ambígua
    (     ) depende da entrada
    EXPLICACAO: Um analisador determinístico constrói UMA árvore por entrada; se a tabela não tem conflitos, a gramática não é ambígua.
DESTAQUE EXAM_TIP: Clássico: 'Mostre que a gramática do if-then-else é ambígua usando `if E1 then if E2 then S1 else S2`' e 'dê uma gramática equivalente não ambígua'. Decore a ideia matched/open: entre um then e um else só pode vir comando 'casado'.
WIDGET PARSE_TREE gramatica=S -> i S | i S e S | x entrada=i i x e x legenda=O contraexemplo clássico, em miniatura.
REVELAR: Por que recursão à esquerda dá associatividade à esquerda?
    RESPOSTA: Em E → E + T, o operando que pode conter outros + é o da ESQUERDA. Em a + b + c, o a + b vira a subárvore da esquerda: (a + b) + c.

=== AULA DE LEITURA [MNEMONIC] Duas árvores, um problema
DESTAQUE MNEMONIC: **Ambi = dois.** Ambidestro usa as duas mãos; gramática ambígua tem DUAS árvores para a mesma frase.
DESTAQUE MNEMONIC: Prova de ambiguidade = **'duas da mesma mão'**: duas mais à esquerda (ou duas mais à direita). Uma de cada mão não vale!
DESTAQUE MNEMONIC: **Precedência = profundidade.** Quem tem MAIS precedência fica MAIS FUNDO na árvore (é calculado antes). O + fica perto da raiz; o * mais embaixo.
DESTAQUE MNEMONIC: **A recursão aponta a associatividade.** E → **E** + T: recursão à esquerda → associa à esquerda. P → B ^ **P**: recursão à direita → associa à direita.
TEXTO: **Palácio da memória**: no Vale das Gramáticas há duas árvores gêmeas plantadas lado a lado, com a mesma placa: `id + id * id`. É o minijogo **Duas Árvores**.
DESTAQUE MNEMONIC: **Else pendurado casa com o vizinho**: o else fica com o if mais próximo que ainda está sem par.
PREVEJA: Em `2 ^ 3 ^ 2` (potência, associativa à direita), qual o agrupamento correto?
    (     ) (2 ^ 3) ^ 2 = 64
    (certa) 2 ^ (3 ^ 2) = 512
    EXPLICACAO: Associativa à direita: o de mais à direita se junta primeiro. 3² = 9, e 2⁹ = 512.
