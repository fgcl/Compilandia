FICHA: Um compilador é uma linha de montagem: léxica → sintática → semântica → código intermediário → otimização → geração de código, com a tabela de símbolos acompanhando todas as fases.
  gancho: Lá Sempre Sai Isso: Ótimo Gol! (Léxica, Sintática, Semântica, Intermediário, Otimização, Geração)
  termos: [léxica, sintática, semântica, código intermediário, otimização, tabela de símbolos]
  erros comuns: [Dizer que variável não declarada é erro sintático (é semântico: depende da tabela de símbolos)., Achar que o léxico detecta palavra-chave digitada errado (`whlie` é um identificador válido)., Confundir fase (divisão lógica) com passada (leitura completa da entrada)., Esquecer a tabela de símbolos e o tratamento de erros, que atravessam todas as fases.]
  FLASH: O que sai da análise léxica? -> Um fluxo de tokens
  FLASH: O que sai da análise sintática? -> Uma árvore sintática
  FLASH: Qual fase faz a verificação de tipos? -> A análise semântica
  FLASH: Front-end x back-end? -> Front-end = análise (entende o fonte); back-end = síntese (gera o código-alvo)
  FLASH: Que erro é `x = (3 + 4;`? -> Sintático
  FLASH: Que erro é `int x = 3 @ 4;`? -> Léxico
  FLASH: Que erro é usar `y` sem declarar? -> Semântico
  FLASH: Por que usar código intermediário? -> m linguagens + n máquinas = m + n peças, e não m × n compiladores

=== AULA DE LEITURA [STORY] A Lanchonete do Compilador
[NARRADOR] Sexta à noite, a Lanchonete do Zé está lotada. Você escreve num papelzinho: 'X-tudo sem cebola + suco de laranja'. Esse papel é o seu **código-fonte**.
[BYTE] Peraí… o que uma lanchonete tem a ver com compilador?
[PROF] Tudo! O pedido passa por uma linha de montagem: cada pessoa faz UMA tarefa e passa adiante. Um compilador é exatamente isso: uma sequência de **fases**.
PASSOS A linha de montagem da lanchonete:
    1. O atendente lê o papel letra por letra e separa os itens: [X-tudo] [sem cebola] [+] [suco de laranja] → **análise léxica** (caracteres viram tokens).
    2. O chefe confere se o pedido está bem montado: 'X-tudo com com batata sem' não é pedido → **análise sintática** (tokens viram árvore).
    3. O gerente confere o SENTIDO: 'suco de feijoada' tem forma de pedido, mas não existe → **análise semântica** (tipos, declarações).
    4. O pedido vira uma comanda padronizada que qualquer cozinheiro entende → **geração de código intermediário**.
    5. A cozinha percebe que dá para esquentar os dois pães na mesma chapa → **otimização**.
    6. O lanche sai pronto → **geração de código** (código de máquina).
[BYTE] E se alguém da linha errar?
[PROF] Cada fase pega um tipo de erro. Letra ilegível é com o atendente (léxico). Pedido sem pé nem cabeça é com o chefe (sintático). Pedido sem sentido é com o gerente (semântico).
PREVEJA: O cliente escreveu 'X-tudo §§ batata'. Quem reclama PRIMEIRO?
    (certa) O atendente (léxico)
    (     ) O chefe (sintático)
    (     ) O gerente (semântico)
    (     ) O cozinheiro (geração de código)
    EXPLICACAO: '§§' nem é um símbolo do cardápio: o atendente não consegue transformar isso em item. Em C, um caractere solto como '@' é erro **léxico**: ninguém depois dele chega a ver o problema.
DESTAQUE BRAIN_POWER: E o caderninho onde o atendente anota o nome de cada cliente e o que ele pediu? Todo mundo da lanchonete consulta esse caderninho…
REVELAR: Quem é o 'caderninho' que todas as fases consultam?
    RESPOSTA: A **tabela de símbolos**: guarda os nomes do programa (variáveis, funções) com tipo, escopo e outras informações. Todas as fases leem e escrevem nela.
DESTAQUE FIRESIDE: Atendente, chefe e gerente ENTENDEM o pedido: são a **análise** (front-end). A cozinha CONSTRÓI a comida: é a **síntese** (back-end). A comanda padronizada é a ponte, troque a cozinha (outra máquina) e o salão continua igual.
DESTAQUE NO_DUMB_QUESTIONS: P: As fases rodam uma depois da outra, cada uma inteira? R: Na prática várias fases são agrupadas numa mesma 'passada', o sintático pede ao léxico 'me dá o próximo token' sob demanda. Mas pensar em fases separadas é o jeito certo de ENTENDER.
REVELAR: Sem olhar: as seis fases, em ordem.
    RESPOSTA: Léxica → Sintática → Semântica → Código intermediário → Otimização → Geração de código. E a tabela de símbolos acompanhando todo mundo.

=== AULA DE LEITURA [WORKED] position = initial + rate * 60, fase por fase
[PROF] Vamos resolver com calma o exemplo mais famoso do Livro do Dragão. Entrada: `position = initial + rate * 60`, com as variáveis declaradas como float.
PASSOS Resolvido, fase a fase:
    1. 1. **Léxica**: ⟨id,1⟩ ⟨=⟩ ⟨id,2⟩ ⟨+⟩ ⟨id,3⟩ ⟨*⟩ ⟨60⟩. O número em ⟨id,1⟩ aponta para a linha de `position` na tabela de símbolos.
    2. 2. **Sintática**: árvore com `=` na raiz; à direita, `+`; dentro do `+`, o `*`: mais embaixo, porque tem precedência maior.
    3. 3. **Semântica**: `rate` é float e `60` é inteiro → insere o nó `inttofloat(60)`.
    4. 4. **Código intermediário**: t1 = inttofloat(60); t2 = id3 * t1; t3 = id2 + t2; id1 = t3.
    5. 5. **Otimização**: converte 60 em 60.0 já na compilação e elimina temporários: t1 = id3 * 60.0; id1 = id2 + t1.
    6. 6. **Geração de código**: LDF R2, id3 / MULF R2, R2, #60.0 / LDF R1, id2 / ADDF R1, R1, R2 / STF id1, R1.
CODIGO (Código intermediário antes de otimizar):
    t1 = inttofloat(60)
    t2 = id3 * t1
    t3 = id2 + t2
    id1 = t3
[BYTE] Como a otimização conseguiu sumir com o inttofloat?
[PROF] Porque 60 é constante! O compilador converte UMA vez, na hora de compilar, em vez de converter toda vez que o programa roda.
DESTAQUE WATCH_OUT: Na tabela de símbolos, position = 1, initial = 2, rate = 3. Por isso `id1`, `id2`, `id3`: é só a ordem em que os nomes apareceram.
TEXTO: Agora é sua vez, num exemplo **esmaecido**: eu começo, você termina. Entrada: `total = preco * 2`, com total e preco do tipo int.
TEXTO: **Léxica**: ⟨id,1⟩ ⟨=⟩ ⟨id,2⟩ ⟨*⟩ ⟨2⟩. **Sintática**: `=` na raiz, `*` à direita com os filhos preco e 2.
REVELAR: **Semântica**: precisa de alguma conversão?
    RESPOSTA: Não! preco é int e 2 é int: int * int = int. Nada de inttofloat. (Se preco fosse float, aí sim: inttofloat(2).)
REVELAR: **Código intermediário** (três endereços)?
    RESPOSTA: t1 = id2 * 2
id1 = t1
REVELAR: **Otimização**: dá para melhorar?
    RESPOSTA: Sim: eliminar o temporário → id1 = id2 * 2. Um otimizador esperto ainda poderia trocar `* 2` por um deslocamento à esquerda (redução de força).
WIDGET TAC gramatica= entrada=a * 2 legenda=Confira com o motor (a no lugar de preco).
DESTAQUE EXAM_TIP: Questão clássica: 'mostre a saída de cada fase para a atribuição X'. Treine com position = initial + rate * 60 até fazer de olhos fechados.

=== AULA DE LEITURA [SOCRATIC] Por que tantas fases?
[PROF] Hoje eu não vou explicar. Vou só perguntar: e você descobre. Chutar errado faz parte.

    (     ) Ninguém: compila normal

REVELAR: Se cada compilador fosse 'direto' de linguagem para máquina, quantos você escreveria? E com um código intermediário no meio?
    RESPOSTA: Direto: 5 × 4 = 20 compiladores. Com código intermediário: 5 front-ends + 4 back-ends = 9 peças. É por isso que existe a divisão front-end / back-end!
DESTAQUE BRAIN_POWER: E se você digitar `whlie (x)` em vez de `while (x)`? O léxico reclama?
REVELAR: Pense: `whlie` combina com o padrão de identificador?
    RESPOSTA: Combina! Letras seguidas de letras é um identificador válido. O léxico aceita feliz; o erro só aparece depois, `whlie (x)` até parece uma chamada de função.
[PROF] Percebeu? Você acabou de deduzir sozinho: o léxico vê **palavras**, o sintático vê **estrutura**, o semântico vê **significado**.
REVELAR: Resuma cada fase de análise em uma pergunta.
    RESPOSTA: Léxica: os caracteres formam palavras válidas? Sintática: as palavras formam frases bem estruturadas? Semântica: as frases fazem sentido (tipos, declarações)?

=== AULA DE LEITURA [FORMAL] Compilador e fases: definições de prova
TEXTO: **Definição.** Um *compilador* é um programa que lê um programa escrito numa linguagem (a linguagem **fonte**) e o traduz para um programa equivalente em outra linguagem (a linguagem **objeto**), relatando os erros detectados no programa fonte.
TEXTO: Um *interpretador*, em vez de produzir um programa objeto, executa diretamente as operações especificadas no programa fonte sobre as entradas fornecidas pelo usuário.
TEXTO: O compilador tem duas partes. **Análise** (front-end): divide o fonte em partes, impõe uma estrutura gramatical, detecta erros e constrói a representação intermediária e a tabela de símbolos. **Síntese** (back-end): constrói o programa objeto a partir da representação intermediária e da tabela de símbolos.
CODIGO (Fases de um compilador (Aho, Lam, Sethi, Ullman, cap. 1)):
    fluxo de caracteres
      → Analisador léxico ............ fluxo de tokens
      → Analisador sintático ......... árvore sintática
      → Analisador semântico ......... árvore sintática (anotada)
      → Gerador de cód. intermediário  representação intermediária
      → Otimizador indep. de máquina . representação intermediária
      → Gerador de código ............ código da máquina-alvo
      → Otimizador dep. de máquina ... código da máquina-alvo
    Tabela de símbolos: compartilhada por todas as fases
PASSOS O que cada fase faz (formato de prova):
    1. **Análise léxica** (scanning): lê os caracteres e os agrupa em lexemas; para cada lexema produz um token ⟨nome-do-token, valor-de-atributo⟩.
    2. **Análise sintática** (parsing): usa os tokens para construir a árvore de sintaxe, que representa a estrutura gramatical.
    3. **Análise semântica**: usa a árvore e a tabela de símbolos para verificar a consistência com a definição da linguagem; tarefa central: verificação de tipos (incluindo coerções).
    4. **Geração de código intermediário**: produz uma representação de baixo nível, fácil de gerar e de traduzir para a máquina-alvo (ex.: código de três endereços).
    5. **Otimização de código**: melhora o código intermediário (mais rápido, menor, menos energia) preservando o significado.
    6. **Geração de código**: mapeia a representação intermediária para a linguagem-alvo, escolhendo registradores e instruções.
DESTAQUE NO_DUMB_QUESTIONS: P: Fase é o mesmo que passada (pass)? R: Não. Fase é uma divisão LÓGICA do trabalho; passada é uma leitura completa da entrada. Várias fases podem ser agrupadas numa única passada.
PREVEJA: Qual fase recebe como entrada um fluxo de tokens?
    (     ) Análise léxica
    (certa) Análise sintática
    (     ) Análise semântica
    (     ) Geração de código
    EXPLICACAO: O léxico PRODUZ tokens; o sintático os CONSOME para montar a árvore.
PREVEJA: Verificação de tipos é tarefa de qual fase?
    (     ) Análise léxica
    (     ) Análise sintática
    (certa) Análise semântica
    (     ) Otimização
    EXPLICACAO: Tipos são significado: a análise semântica consulta a árvore e a tabela de símbolos para checá-los e inserir coerções.
DESTAQUE EXAM_TIP: Em questão discursiva, escreva para cada fase o trio **entrada → o que faz → saída**. E cite a tabela de símbolos e o tratamento de erros, que atravessam todas as fases.
REVELAR: Diferença entre compilador e interpretador, em uma linha.
    RESPOSTA: O compilador traduz o programa inteiro para um programa-alvo (que depois executa); o interpretador executa o fonte diretamente. O código compilado costuma ser mais rápido; o interpretador costuma dar diagnósticos de erro melhores.

DESTAQUE MNEMONIC: Zoom crescente: **letra → palavra → frase → sentido**. O léxico junta letras em palavras; o sintático junta palavras em frases; o semântico pergunta se a frase faz sentido.
TEXTO: Frase famosa de Chomsky: *'Ideias verdes incolores dormem furiosamente.'* Palavras válidas ✓ (léxico ok), frase bem montada ✓ (sintaxe ok), sentido zero ✗ (a semântica reclamaria!).
PREVEJA: 'O gato bebeu o.': em que nível está o problema?

    (certa) Estrutura (sintaxe)
    (     ) Sentido (semântica)
    EXPLICACAO: Todas as palavras existem, mas a frase termina no meio: falta o complemento. Problema de estrutura = sintático.
DESTAQUE WATCH_OUT: Confusão clássica: 'variável não declarada' NÃO é erro sintático. `y = 5;` tem estrutura perfeita; só a tabela de símbolos sabe que `y` não existe → erro semântico.
